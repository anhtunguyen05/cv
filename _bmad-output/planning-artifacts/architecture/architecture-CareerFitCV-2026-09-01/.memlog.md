- (constraint) Canonical PRD is the product authority: MVP includes account access, structured CV Profile, immutable CV Version, pasted Job Description, deterministic Match Report, Template Preview, and browser print/HTML Export; AI Patch, provider integration, worker PDF, and multi-agent work are later.
- (decision) Preserve structured CV data as the canonical domain representation; prevent independent components from introducing free-form CV state.
- (decision) Refine the architecture boundary: Laravel owns trusted state and User ownership; Vue owns interaction; the Python worker remains optional and is not an MVP dependency.
- (decision) Preserve mutable CV Profile plus immutable named CV Version snapshots; reports, previews, and exports pin exact CV Version sources.
- (decision) Preserve proposal-only AI and explicit human approval for later Patch work; AI providers never write trusted state directly.
- (decision) Preserve single controlled orchestrator before multi-agent expansion; add agents only after measured need.
- (decision) Replace the stale docs claim that Laravel health is GET /health with the source-verified GET /api/health; retain worker /health as a separate alias.
- (question) Resolve before production: browser authentication mechanism, database deployment standard, template representation, matching quality threshold, retention policy, and server-side export trigger.
- (event) Architecture spine finalized after source comparison, AD-4 refinement, mechanical lint, adversarial review, and repository reality check.
- (decision) Documentation work uses the Coaching path. Its primary audience is CareerFitCV developers and implementation agents; the stable docs must provide globally shared rules and contracts without duplicating epic or story behavior.
- (decision) Adopt docs/ as the stable global documentation layout: architecture/ for overview and ADRs, standards/ for cross-epic engineering rules, contracts/ for stable component agreements, and domain/ for glossary and cross-epic domain invariants. Existing top-level documents will be consolidated deliberately without duplicate sources of truth.
- (decision) Global documentation covers MVP rules and post-MVP AI/worker guardrails. Post-MVP material must be explicitly marked Deferred or Post-MVP and must constrain future integrations without creating an implementation commitment.
- (decision) MVP first-party Vue SPA authentication uses Laravel Sanctum stateful cookie sessions with CSRF protection. The browser must not retain bearer tokens or JWTs in local storage. Protected product endpoints use auth:sanctum and Laravel ownership policies. Mobile or third-party API tokens are deferred.
- (decision) Product endpoints are versioned under /api/v1; /api/health remains a separate operational payload. Successful resource responses use a data envelope, paginated collections add meta and links, and all product errors use code, message, and details. Validation errors are keyed in details; raw framework exceptions are never client contracts. request_id is deferred until observability is implemented.
- (decision) MySQL 8.4 is the canonical database for shared development, integration and end-to-end verification, and production. SQLite is permitted only for local fast unit/scaffold work and cannot prove production migration, query, or constraint compatibility. PostgreSQL is out of MVP scope. Redis is optional and cannot be required for the core MVP flow.
- (decision) Existing Laravel users and system tables retain their current bigint keys. Every new product aggregate uses a ULID string as its primary and public API identifier; relationships between new aggregates use the same ULID type. Clients never generate trusted identifiers. Authorization remains enforced by ownership policies and does not rely on identifier opacity.
- (decision) Verification is risk-based, with no global coverage percentage. Use PHPUnit for PHP domain/application and Laravel HTTP feature tests, Vitest for Vue/TypeScript unit and component/composable tests, a MySQL 8.4 integration profile for migrations/persistence/policies/API contracts, and Playwright for browser E2E of critical MVP journeys. Every story maps acceptance criteria to suitable tests; deterministic behavior uses fixtures and repeatability tests; regressions require a test. E2E reset operations may run only against a declared disposable database.
- (decision) CV data, raw Job Descriptions, authentication material, cookies, credentials, and raw AI prompts/outputs are sensitive and must not enter ordinary application logs. Audit records are distinct from logs and contain only actor, action, resource ULID, outcome, timestamp, and sanitized metadata by default. Post-MVP AI audit records retain provider/model, prompt-template version, timing, status, redacted metadata, and references; raw payload retention is blocked on Epic 5 retention/deletion policy. User content and artifacts are private by default.
- (decision) Laravel FormRequest owns HTTP shape, types, authentication context, and basic boundary constraints. Domain and application layers enforce business invariants, ownership, immutable snapshots, and state transitions for every caller. Frontend Zod/VeeValidate schemas provide early UX feedback only and never override the API contract. Contract changes update API docs, backend validation, frontend schema, and tests within the same story.
- (decision) All /api/v1 failures, including router, middleware, authentication, CSRF/session, authorization, throttling, validation, and exception failures, render the shared JSON contract. Pagination uses documented page-number semantics. Async results are scoped, idempotent, snapshot-bound, and Laravel-validated. Global standards use stable rule IDs; accessibility states are global requirements.
- (event) Global documentation architecture finalized after lint, reality check, adversarial review, and input reconciliation.
